# Building MicroGPT for iOS

This app started Android-only. iOS support was added without changing any
Android code. This doc is the practical playbook for building and shipping
the iOS app via EAS.

> **Android is untouched.** No file under `android/`, no Kotlin in
> `modules/*/android/`, and no Android-only JS branch was modified. Every
> JS change is additive behind `Platform.OS` — the Android code paths
> resolve exactly as before. You can keep shipping Android with no changes.

---

## 1. How the iOS build works (read this first)

The project is a **bare** Expo project for Android (`android/` is committed)
but uses **CNG (Continuous Native Generation)** for iOS: the `ios/` folder is
**not** committed and is **generated by EAS on its macOS builder** at build
time from `app.config.js` + the module podspecs.

Why: a **Windows** machine literally cannot generate the iOS project
(`expo prebuild -p ios` prints _"Skipping… run from macOS or Linux"_). So
there is nothing to commit, and trying to hand-maintain `ios/` on Windows
would only drift from the config. EAS does the right thing automatically:

- `eas build -p ios` → no `ios/` dir present → EAS runs `expo prebuild`
  for iOS, `pod install`, then builds. Your committed `android/` is not
  touched (prebuild is platform-scoped).
- `eas build -p android` → uses the committed `android/` as-is.

`/ios/` is in `.gitignore` (anchored to the repo root so it does **not**
ignore the hand-written Swift in `modules/*/ios/`).

You never run prebuild yourself. Don't commit an `ios/` folder.

### Why the mixed state (committed `android/`, generated `ios/`) is safe

EAS decides "use the committed native folder" vs. "prebuild it" **per
platform**, not globally. From the eas-cli source
(`resolveWorkflowAsync`): for Android it looks for
`android/app/build.gradle`; for iOS it looks for
`ios/<App>.xcodeproj/project.pbxproj`. If the marker exists (and isn't
gitignored) that platform is `GENERIC` (committed, no prebuild); otherwise
it's `MANAGED` (prebuild). So:

- **android/** committed → `GENERIC` → never prebuilt, never modified.
- **ios/** absent + gitignored → `MANAGED` → prebuilt fresh on each build.

### Expected `npx expo-doctor` warnings (safe to ignore)

- _"Check for app config fields that may not be synced in a non-CNG
  project"_ — a generic advisory triggered by the committed `android/`. It
  does **not** apply to iOS, which is generated from `app.config.js` on
  every build. Android's native config was already baked in when its folder
  was generated; we don't change Android config here.
- The 19 _"packages out of date"_ patch-version notes are pre-existing and
  unrelated to iOS — see `docs/UPDATING.md` for the deliberate update flow.
- The two local modules are excluded from the React Native Directory check
  in `package.json` (they're local, not npm packages).

## 2. One-time setup

### 2.1 Apple account / credentials
Your Apple account is logged into EAS, so credentials are automatic. The
bundle identifier is **`com.meteormeta.MicroGpt`** (matches the Android
`package`). The first `eas build -p ios` will offer to create the
distribution certificate + provisioning profile / register the bundle id —
say yes.

### 2.2 EAS secrets (env vars baked into the JS bundle)
The same three the Android build needs, plus two iOS-only Google ones.
Set any that aren't already set:

```powershell
eas secret:create --scope project --name EXPO_PUBLIC_SUPABASE_URL --value "https://YOURPROJECT.supabase.co"
eas secret:create --scope project --name EXPO_PUBLIC_SUPABASE_PUBLISHABLE_KEY --value "sb_publishable_..."
eas secret:create --scope project --name EXPO_PUBLIC_GOOGLE_WEB_CLIENT_ID --value "....apps.googleusercontent.com"
```

### 2.3 Google Sign-In on iOS (optional — email auth works without it)
iOS needs its **own** Google OAuth client (the web client id won't work for
the native iOS flow). In Google Cloud Console → Credentials → Create OAuth
client → **iOS**, bundle id `com.meteormeta.MicroGpt`. It gives you the id in
two forms; set both as secrets:

```powershell
# forward form: 1234-abcd.apps.googleusercontent.com
eas secret:create --scope project --name EXPO_PUBLIC_GOOGLE_IOS_CLIENT_ID --value "1234-abcd.apps.googleusercontent.com"
# reversed form: com.googleusercontent.apps.1234-abcd
eas secret:create --scope project --name EXPO_PUBLIC_GOOGLE_IOS_URL_SCHEME --value "com.googleusercontent.apps.1234-abcd"
```

Until these are set, the iOS app builds and runs fine — only the "Sign in
with Google" button is non-functional on iOS (email sign-in still works).

`.env.example` documents all of these for local dev too.

## 3. Build commands

```powershell
# TestFlight / App Store build (recommended first real build):
eas build --platform ios --profile production

# Internal test build for a registered device (ad-hoc):
eas build --platform ios --profile preview
```

Submit to TestFlight/App Store:
```powershell
eas submit --platform ios --latest
```

`eas.json` now has `ios` blocks on `development`, `preview`, and
`production` (production = store distribution, autoIncrement build number
via `appVersionSource: remote`).

runtime-test it from a TestFlight/device build (§3) since iOS native code
can't be run from Windows.

## 5. How iOS image generation works (Core ML)

iOS can't use the Android image engines (one runs a child **process** — not
allowed in the iOS sandbox — the other is Qualcomm-NPU only). The iOS
implementation uses **Apple Core ML Stable Diffusion**
([`apple/ml-stable-diffusion`](https://github.com/apple/ml-stable-diffusion) v1.1.1),
mapped onto the existing `ExpoStableDiffusion` JS contract so
`lib/image-gen-service.ts` and the chat/combo flows work unchanged.

**Native engine** — `modules/expo-stable-diffusion/ios/ExpoStableDiffusionModule.swift`
drives `StableDiffusionPipeline` on the Neural Engine (`cpuAndNeuralEngine`,
`reduceMemory`, `disableSafety`). The Apple library is vendored (MIT) under
`ios/vendor/StableDiffusion/` as its own pod; `plugins/withStableDiffusionIOS.js`
injects it into the EAS-generated Podfile and sets the iOS deployment target
to 16.0. SDXL is gated to iOS 17 (base SD is 16.2). The pipeline is released
after each generation to reclaim the 1-2 GB it holds.

**Models** — Core ML models are *directories* of compiled `.mlmodelc`
bundles, not GGUF. `lib/coreml-models.ts` lists Apple's official repos
(`coreml-stable-diffusion-2-1-base`, `-v1-5`) and downloads each model by
enumerating the HuggingFace tree (`/api/models/<repo>/tree/...`) and fetching
every file under `split_einsum/compiled/` to its relative path — so there's
no native unzip (and no new Android dependency). It skips the monolithic
`Unet.mlmodelc` (the pipeline prefers the ANE chunks), the img2img-only
`VAEEncoder`, and the `SafetyChecker` to save ~1.5 GB. These models appear in
the catalog only on iOS; the Android-format image models are hidden there.

**To runtime-test:** build a device/TestFlight build (§3), install on an
iPhone (iOS 16.2+; A14/iPhone 12 or newer recommended for the ANE), download
"SD 2.1 base (Core ML)" from the image-gen catalog, then generate. First
generation compiles the ANE model (slow, ~1 min); subsequent runs are fast.

Reference implementation that informed this:
<https://github.com/alichherawalla/off-grid-mobile-ai> (`ios/CoreMLDiffusionModule.swift`).

## 6. What changed for iOS (file map)

| Area | Files |
|---|---|
| App config (bundle id, Info.plist, Google iOS scheme, iOS EAS profiles) | `app.config.js`, `eas.json`, `.env.example` |
| Google Sign-In iOS client | `lib/auth.ts` |
| Cross-platform storage paths (iOS → Documents, Android → public Downloads) | `lib/storage-paths.ts` + call sites in `store/useModelsSlice.ts`, `lib/image-gen-service.ts`, `app/(root)/(tabs)/home.tsx`, `components/ImageGenerationView.tsx` |

| Image gen (iOS, Core ML) | `modules/expo-stable-diffusion/ios/*`, `modules/expo-stable-diffusion/expo-module.config.json` |
| Enable native downloader on iOS; hide Android image models on iOS | `store/useModelsSlice.ts` (additive `Platform.OS` branches) |

Verify the JS at any time with `npx tsc --noEmit` and the config with
`npx expo config --json` — both pass on Windows.
